# 인력 계획 관리

**채용부터 퇴직까지 직원의 전체 생애주기를 다루는 오픈 소스 인사 플랫폼.**

인력 계획 관리(WPM)는 채용, 근태와 휴가, 직원 개발, 인력 계획, 급여를 하나의 애플리케이션에 통합합니다. 평가와 참조 설계를 위한 데모 소프트웨어입니다.

언어: العربية, বাংলা, Cymraeg, English, Español, हिन्दी, 日本語, 한국어, Русский, اردو, 中文

> **데모 소프트웨어이며 아직 운영 환경에서 사용할 준비가 되어 있지 않습니다.** WPM은 합성 데이터만 사용하며, 법정 계산은 예시입니다. 실제 개인 데이터를 입력하지 마십시오. [운영 환경으로 가는 길](path-to-production/index.md)은 운영 환경 사용에 무엇이 필요하며 각 부분이 얼마나 준비되어 있는지 설명합니다. [규제 관점](../../spec/regulatory.md)도 참고하십시오.

## 장점

인사 데이터는 지원자 받은편지함, 휴가 스프레드시트, 근무표 보드처럼 서로 다른 도구에 흩어져 있는 경우가 많습니다. 도구 사이에서 옮길 때마다 수작업이 늘고 오류 위험이 커집니다. WPM은 이러한 이동을 줄이도록 설계되었습니다.

- **단일 시스템.** 입사 절차, 휴가, 교육, 급여 기록을 하나의 애플리케이션에서 보관하므로 재입력이 줄어듭니다.
- **데이터 최소화.** 보관하지 말아야 할 데이터에는 필드가 없고, 공개하지 말아야 할 데이터에는 API 경로가 없습니다. 예를 들어 진단 필드가 없으며, 펄스 설문 응답에는 작성자가 없습니다.
- **보고 규칙.** 알 수 없는 값을 0으로 보고하지 않고, 집계로 개인을 식별할 수 없게 하며, 추정에는 그 근거를 밝힙니다.
- **현지화.** 애플리케이션은 25개 로캘로, 역할별 브리프는 21개 로캘로 제공되며 오른쪽에서 왼쪽으로 쓰는 언어도 포함됩니다. 국가별 규칙은 데이터로 보관됩니다. 번역은 AI가 작성했으며 원어민의 검토를 받지 않았습니다.
- **추적 가능성.** 소스 코드는 공개되어 있으며, 각 동작은 번호가 매겨진 요구 사항, 설계 결정, 작업으로 추적됩니다.
- **독립적인 배포.** 구성은 Rust JSON API, SvelteKit 클라이언트, PostgreSQL입니다. 새로 복제한 저장소에서 빌드되며, 자매 애플리케이션과의 연동은 선택 사항입니다.

## 기능

- **채용과 기록.** 채용 요청, 지원자 파이프라인, 입사 절차, 직원 기록, 조직도.
- **근태와 일정.** 근태와 휴가, 근로 시간 점검이 있는 교대 근무, 교대와 알림이 있는 대기 근무표, 직원 명부.
- **개발.** 평가, 360도 피드백, 학습, 역량 격차 분석, 교육 시간 권고, 필수 학습.
- **계획과 보고.** 전략적 인력 계획, 지표와 인사이트, CEO 대시보드.
- **입사자와 퇴사자.** 날짜가 있는 체크리스트와 감사 추적이 있는 마지막 근무일 인수인계.
- **커뮤니케이션.** 대상, 링크, 읽음 수가 있는 공지.
- **직원 권리와 웰빙.** 웰빙 안내, 익명 펄스 설문, 조정 사항, 정보 주체 접근, 삭제, 보존.
- **급여.** 급여와 보상, 예시용 법정 계산.

## 비교

이 표는 WPM을 세 범주의 인사 시스템과 비교합니다. 벤치마크가 아니라 전반적인 안내입니다. [제품별 비교](../../docs/compare/index.md)도 참고하십시오.

| | WPM | 올인원 제품군 (Workday, SAP SuccessFactors, BambooHR) | 오픈 소스 인사 (frappe/hrms, OrangeHRM, Horilla, Odoo HR) | 단일 기능 도구 (Greenhouse, Lever, Gusto, ADP) |
| --- | --- | --- | --- | --- |
| **범위** | 채용부터 퇴직까지 전체 생애주기 | 하나의 플랫폼에서 비슷한 범위 | 같은 핵심 기능 | 하나의 기능 |
| **라이선스** | 오픈 소스 | 상용 | 오픈 소스 | 상용 |
| **주요 강점** | 데이터 최소화, 추적 가능한 설계, 역량 격차와 교육 시간 분석 | 통합되고 지원되는 하나의 플랫폼 | 더 많은 연동, 현지화, 배포 사례 | 하나의 기능에 대한 깊이 |
| **적합한 경우** | 평가, 참조 설계 또는 추가 개발 | 지원되는 시스템이 필요한 조직 | 운영 환경에서 오픈 소스를 원하는 조직 | 한 기능의 깊이가 필요하고 나머지는 직접 연동할 수 있는 조직 |

## 대상 독자

- **경영진.** [역할별 브리프](for/index.md)는 각 리더 역할에 WPM이 무엇을 제공하는지, 그 결과를 어떻게 읽는지 설명합니다.
- **인사 팀.** [데모 튜토리얼](start/index.md)은 가상의 데이터로 각 페이지를 안내합니다.
- **개발자와 아키텍트.** [명세](../../spec/index.md)와 [설치 안내](../../INSTALL.md)를 참고하십시오.
- **평가자.** [준비 상태 평가](../../spec/readiness-assessment.md)는 WPM과 운영 환경 사용 사이의 차이를 정리합니다.

## 도움 받기

- **버그를 신고하거나 질문하려면** [이슈 트래커](https://github.com/workforce-planning-management/workforce-planning-management/issues)를 이용하십시오. 페이지, 수행한 작업, 기대한 결과, 실제 결과를 적어 주십시오. 실제 개인 데이터는 포함하지 마십시오.
- **보안 문제를 신고하려면** 공개 이슈가 아니라 [보안 정책](../../SECURITY.md)에 설명된 대로 이메일로 보내십시오.
- **애플리케이션에서 작업 배우기.** 애플리케이션 머리글의 **도움말** 링크는 도움말 페이지와 직원, 관리자, 인사 담당자를 위한 안내를 엽니다. 각 오류 메시지에도 이 링크가 있습니다.

## 다음 단계

3. **의견을 보내 주십시오.** [의견을 내는 방법](../../RFC.md)과 [기여하는 방법](../../CONTRIBUTING.md)을 참고하십시오.
