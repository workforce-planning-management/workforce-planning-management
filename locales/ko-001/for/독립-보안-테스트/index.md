# 독립 보안 테스트

**관점:** 이 소프트웨어를 쓰지 않은 사람들이 공격해 보게 하려면 어떻게 해야 하는가, 무엇을 겨냥하도록 알려 주어야 하는가, 그들이 찾은 것으로 무엇을 해야 하는가?

독립적인 테스트는 이루어지지 않았습니다. [위협 모델](../../../../spec/governance/threat-model.md)은 소프트웨어를 쓴 바로 그 어시스턴트가 썼고 다른 누구도 검토하지 않았으며, 거기에 나온 모든 통제는 그 작성자가 동작을 확인했습니다. [준비 상태 평가](../../../../spec/readiness-assessment.md)는 독립적인 침투 테스트를 사람만 닫을 수 있는 관문으로 나열합니다(WPM-T201, **미완료**). 이 페이지는 테스트를 의뢰하는 사람을 위한 브리프입니다. 테스터가 작성한 테스트 계획이 아니며 그것을 대신하지도 않습니다.

## 테스터에게 줄 것

| 항목 | 위치 | 비고 |
| --- | --- | --- |
| 공격할 배포 | 직접 마련: [배포 안내](../../../../spec/operations/deployment.md) | 로그인을 **켠** 운영 환경 설정, 테스트용 ID 공급자, **합성 데이터만**. 실제 사람의 기록으로 테스트하지 마십시오 |
| 소스 | 이 저장소 | 소스를 쓰는 테스트가 블랙박스 테스트보다 철저합니다. 어느 쪽을 원하는지 알려 주십시오 |
| 위협 모델 | [governance/threat-model.md](../../../../spec/governance/threat-model.md) | 24개의 위협, 구현된 통제, 격차. 아무 안내 없이 무엇을 찾아내는지 보고 싶다면 첫 블랙박스 시도 **뒤에** 주십시오 |
| API 설명 | `GET /api-docs/openapi.json` | 모든 경로. 무언가를 바꾸는 모든 작업에는 `Idempotency-Key`가 붙음 |
| 로그인 설계 | [auth.md](../../../../spec/auth.md), [operations/entra-sign-in.md](../../../../spec/operations/entra-sign-in.md) | 페르소나, 속성, 그리고 정책이 동작만으로 판단하는 것 |
| 테스트용 ID | 직접 생성 | 최소한: 속성이 없는 근로자, 직속 관리자, 보고 체계 밖의 관리자, 인사, 급여, 관리자, 서비스 피어 |

## 살펴보도록 요청할 것

작성자가 확인하지 못한 것들입니다. 각 행은 위협 모델의 해당 항목을 밝히므로 발견 사항을 추적할 수 있습니다.

| 영역 | 시도할 것 | 위협 |
| --- | --- | --- |
| 토큰 | 알고리즘 혼동, 요청이 진행되는 동안 교체되는 키 세트, 만료되었거나 아직 유효하지 않은 토큰, 다른 대상용 토큰 | T1, T2 |
| 알 필요성 | 속성이 없는 호출자와 옆자리 사람으로서 모든 읽기 경로. 분류 표에 없는 경로. 정책은 허용하지만 핸들러는 거부해야 하는 쓰기 | T3, T4, T6 |
| 권한 속성 | 토큰의 속성을 추가, 재전송, 상속할 수 있는지. 누가 발급할 수 있는지. 공유되었거나 오래 유효한 관리자 | T24 |
| 인젝션 | 모든 매개변수, 경로 구간, 본문 필드에 대한 퍼징. 삭제와 보존 구문은 형식이 있는 식별자로 만들어지며 읽어 보았을 뿐 퍼징하지는 않았음 | T12 |
| 브라우저 클라이언트 | 인터페이스 서버의 세션 처리, 세션을 토큰으로 교환하는 방식, 저장된 텍스트를 통한 크로스 사이트 스크립팅, 콘텐츠 보안 정책 우회, 버전 고정 없이 공개 네트워크에서 스크립트를 불러오는 콘텐츠 관리자 페이지 | T13, T14 |
| 외부로 나가는 요청 | 설정된 모든 URL(키 세트, 자매 서비스, 공유 캐시)을 통한 서버 측 요청 위조 | T15 |
| 제한 | 본문 한도, 요청 시간 제한, 인스턴스별 요청 제한, 조직 전체의 기록을 메모리로 읽어 들이는 보기 | T16, T17 |
| 로그 | 개인 데이터, 토큰, 쿼리 문자열이 로그에 들어가는지 | T19 |
| 멱등성 키 | 두 호출자가 쓴 키. 본문, 경로, 쿼리를 바꾼 같은 키. 거의 유효한 키. 매우 큰 본문. 하나의 키로 경쟁하는 두 요청(이 주장은 추론한 것이며 테스트로 경쟁시켜 보지 않았음). 저장된 응답을 호출자 외의 누군가 읽을 수 있는지 | 신규 |
| 감사 추적 | 항목을 바꾸거나, 지우거나, 건너뛰는 모든 방법. 체인 검증 엔드포인트 | T7 |
| 백업 | 변조되었거나 키가 잘못된 백업에서의 복원. 삭제된 사람이 돌아오는지 | T10, T11 |
| 공급망 | 빌드 액션 고정, 비밀 값 스캔, 이미지 서명 | T20, T21 |

## 시작 전에 정해 둘 규칙

귀사의 보안 팀과 법무 팀과 함께 채우십시오. 여기서는 아무것도 정해지지 않습니다.

- **권한:** 테스트가 승인되었음을 누가 서명하는지, 어느 시스템과 주소가 대상인지.
- **기간:** 날짜와 시간대(일 수로 계산), 중단시킬 때 연락할 사람.
- **범위:** 포함되는 것(API, 인터페이스, 로그인 흐름, 백업 스크립트)과 제외되는 것(ID 공급자 자체의 서비스, 귀사의 네트워크, 다른 시스템과 공유하는 모든 것).
- **데이터:** 합성 데이터만. 테스터가 실제 개인 데이터를 발견하면 누구에게 알리고 어떻게 처리하는지.
- **파괴적 테스트:** 서비스 거부, 대량 쓰기, 삭제를 허용하는지, 허용한다면 어디서인지.
- **보고:** 형식, 심각도 척도, 받는 사람, 보관할 수 있는 기간, 찾은 비밀 값의 처리 방법.
- **재테스트:** 계약에 수정 사항 확인이 포함되어 있는지.

## 발견 사항으로 할 일

1. 각각을 테스터의 참조 번호, 증거, 부여한 심각도와 함께 [tasks.md](../../../../spec/tasks.md)의 작업으로 기록합니다. 이의가 제기된 발견 사항은 이유와 함께 이의 제기됨으로 남겨 둡니다.
2. 먼저 실패하는 테스트를 쓰고 수정합니다. 수정이 규칙이라면 위협 모델의 격차 열에 추가하고, 재테스트를 통과했을 때만 거기서 닫습니다.
3. 보고서가 손에 있고, 모든 발견 사항에 담당자가 있고, 재테스트가 끝나기 전까지는 WPM-T201을 완료로 표시하지 마십시오. 같은 변경에서 [준비 상태 평가](../../../../spec/readiness-assessment.md)와 관문 목록(WPM-T203)을 갱신하십시오.
4. 악용될 수 있는 내용이 있다면 보고서를 저장소 밖에 두고 보관 위치로 링크하십시오.

## 문제 없는 보고서가 의미하는 것과 의미하지 않는 것

발견 사항이 없는 테스트는 이 테스터들이 이 기간에 이 범위와 이 ID로 아무것도 찾지 못했음을 보여 줍니다. 결함이 없음을 보여 주지 않으며, 이후에 바꾼 설정을 포괄하지 않고, 다른 관문을 대신하지도 않습니다. 다른 관문이란 접근성 감사, 승인된 개인정보 영향 평가, 귀사 플랫폼에서의 복원 훈련입니다.

## 이 페이지가 하지 않는 것

공급업체를 지명하거나, 가격을 정하거나, 표준을 약속하지 않습니다. 귀사의 업계가 테스터에게 어떤 제도나 인증을 기대하는지는 직접 결정하십시오.
